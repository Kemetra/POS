RT-859 · G-6 Diagnostics addendum: the catalogue check lists the matched items

The «فحص الكتالوج» search panel lists each match (name, pack, SKU, price) instead of only a count. Drawn at 1024×768 and 1280×800, in light and in forced colours. Gap G-10, owner decision D7 (RT-536), slice P-26-3 step 1. The implementation is RT-860.

Approved 2026-10-24 under owner delegation (RT-859 comment 13739): OD-1…OD-6 as drawn. No runtime code, bridge or contract changes. Every field drawn is one catalogue.search already returns on POS main@be087a4f.

Correction to comment 13689. That comment says the barcode is filled "only for a barcode hit" and does not list sku. On main, the Diagnostics check calls search only (DiagnosticsBridge, src/renderer/routes/app/CatalogueDiagnostics.tsx:57). A search row always carries sku and never carries selling_barcode. A typed barcode still finds its product. On read-down data, each aliases[] entry, barcodes included, goes into aliases_json (read-down/map-sellable-row.ts:25, :169) and so into alias_fold (read-down/read-down-writer.ts:146). Search substring-matches alias_fold (search.ts:52). The row that comes back has a name, SKU and price, but no barcode. This is frame C2.

On read-down data only. The dev seed (dev-seed-catalogue.ts) keeps its barcodes in product_barcodes and folds only its name aliases into alias_fold. On the dev seed, the C2 query returns not_found («لا توجد نتائج»). Test C2 against a terminal with a real read-down, or with fixture data that puts the barcode in aliases.

Other limits on main: at most 20 rows (search.ts:21 SEARCH_CAP; product-repo.ts:196). Fewer than 2 normalized characters gives too_short in main (catalogue-bridge.ts:46, :163). The renderer already blanks the result for a trimmed query under 2 characters, before it calls (CatalogueDiagnostics.tsx:151–152). The line text comes from searchMessage (diagnostics-model.ts:61–72), which shows refused, too_short and catalogue_unavailable all as «غير متاح».

2 · Layout and row

  • The frozen 2×2 grid is kept (G6-Diagnostics). The device and sync panels are unchanged. Only the second grid row takes the free height. The counts panel keeps its own height. The search panel stretches to the bottom of the screen, and its list scrolls inside the panel. Nothing else on the page moves.
  • Panel order: field, then the shipped count line («5 نتائج»), then the list, then (only when truncated) the limit line.
  • Row: on the inline start, the name (display_name_ar, 15px semibold at 1280 and 14px at 1024; it wraps and is never cut). Under the name, the pack label and the SKU in muted 13px, the SKU in mono with dir="ltr". On the inline end, the price in the money family: Dubai with tabular lining numerals, semibold, with dir="ltr" isolation. Prices line up down the list.
  • Read-only: a row has no action and no selection (this is Diagnostics, not the sale). The list is one tab stop (tabindex="0"), so a keyboard can scroll it. No row takes focus. The list's accessible name is the shipped «نتائج البحث».
  • Visible rows before scrolling: about 4 at 1024×768 and about 4½ at 1280×800. The count line always gives the full number returned.
